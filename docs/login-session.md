# 로그인 세션 판정과 배포

이 문서는 MCP 로그인 브라우저의 세션이 저장되지 않던 원인과, 실행 중인 설치에 반영하는 절차를 적는다.

## 원인

`naver_blog_confirm_login`은 이 프로세스의 Playwright 컨텍스트만 본다. 사용자가 따로 연 Chrome 창의 로그인과는 쿠키가 공유되지 않는다.

확인 로직은 `NID_AUT`와 `NID_SES`가 둘 다 있을 때만 로그인으로 보았다. 로그인 유지 없이 `NID_SES`만 있는 정상 세션은 실패로 처리됐다. 그 다음 같은 페이지를 `https://section.blog.naver.com/`으로 이동했다. 이동된 창은 `BlogHome.naver`에서 로그인 버튼을 보여 주었고, 세션 파일은 저장되지 않았다. 이후 카테고리 조회와 글쓰기는 `네이버 로그인이 필요합니다`를 반환했다.

캡차나 2단계 인증이 보이는 동안에도 남은 쿠키만으로 로그인 성공을 반환할 수 있었다. 로그인 칸이 비어 있거나 영어 `Sign in` 버튼을 못 찾아도 제출된 것처럼 보이는 상태가 반환될 수 있었다.

`NAVER_BLOG_ID`는 로그인 폼에 넣는 아이디이자, 별도 설정이 없으면 글쓰기 URL의 블로그 아이디다. 발행 대상이 다르면 `NAVER_PUBLISH_BLOG_ID`로 구분한다. 에디터 URL이 그 값과 다른 블로그로 열리면 본문을 입력하지 않는다.

## 세션 파일

- 경로 기본값은 `playwright-state/auth.json` (`SESSION_STORAGE_PATH`로 바꿀 수 있다).
- 확인이 실패하거나 쿠키가 오래되어 보여도 이 파일을 삭제하지 않는다.
- 파일 수정 시각이 24시간을 넘어도 그 이유만으로 버리지 않는다. `NID_AUT` 또는 `NID_SES`가 있으면 재사용한다.
- 프로브가 예외로 끝나면 불러온 컨텍스트를 유지한다. 로그인 안 된 것이 확인된 경우에만 메모리 속 컨텍스트를 닫고, 파일은 남긴다.
- 이 변경을 배포할 때 기존 `auth.json`을 지우지 않는다. 그 파일에 유효한 쿠키가 있으면 재로그인 없이 재사용할 수 있다.
- IP보안이 켜진 채로 만들어진 세션은 블로그에서 다시 로그인을 요구할 수 있다. 그 경우에도 파일을 자동으로 지우거나 로그인을 다시 시작하지 않는다. 사용자가 다음에 `naver_blog_login`을 실행할 때만 IP보안을 끄고 자격 증명을 제출한다.

## 설정

| 변수 | 역할 |
| --- | --- |
| `NAVER_LOGIN_ID` | 로그인 폼에 입력할 네이버 아이디. 비우면 `NAVER_BLOG_ID`. |
| `NAVER_PUBLISH_BLOG_ID` | 글을 쓸 블로그 아이디. 비우면 `NAVER_BLOG_ID`. |
| `NAVER_BLOG_ID` | 위 두 값의 기본값. |
| `NAVER_BLOG_PASSWORD` | 로그인 비밀번호. 응답이나 로그에 출력하지 않는다. |

로그인 아이디와 발행 블로그를 바꾸려면 비밀번호를 다른 아이디에 맞춰 다시 적지 말고, 각 변수를 실제 의미에 맞게 둔다.

## 실행 중 설치에 반영

대상 예: `/home/box/mcp/naver-blog-mcp` (Playwright 1.55, `.venv`). 이 저장소 작업은 그 디렉터리를 수정하지 않는다.

1. 기본 브랜치에 병합하지 않은 상태로, 원하는 커밋을 그 체크아웃에 가져온다.
2. `playwright-state/auth.json`을 삭제하지 않는다.
3. 의존성 선언은 그대로다. 필요하면 `uv sync`만 한다. Playwright 버전이 1.55로 유지되면 Chromium을 다시 설치하지 않는다.
4. MCP 서버 프로세스를 재시작해 새 코드를 읽게 한다. 재시작 전에 세션 파일을 지우지 않는다.
5. 서버는 저장된 쿠키를 먼저 읽는다. 쿠키가 유효하면 `naver_blog_login`을 호출하지 않는다.
6. 다음에 사용자가 직접 로그인을 요청하면, 그 MCP Chromium에서 IP보안을 끈 다음 자격 증명을 제출한다. 2단계 인증이나 캡차가 보이면 성공으로 보고하지 않고 사용자가 마칠 때까지 둔다.

확인 응답의 `diagnostics`에는 쿠키 이름, 호스트, 경로, 설정된 로그인 아이디와 발행 블로그만 있다. 쿠키 값, 비밀번호, 쿼리스트링은 넣지 않는다.
